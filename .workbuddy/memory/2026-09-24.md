**任务**：为用户设计一款基于 Node.js 的 SSH 客户端，整理功能框架说明文件与需求，给出实现计划（本轮只出文档，未写代码）。

- 首版范围：**完整功能版**（非 MVP）
- 前端栈：**React + TypeScript + Tailwind**

**产出文件**
- `docs/01-功能框架与需求说明书.md` —— 产品定位、架构、技术选型、F1~F10 功能清单（MoSCoW 分级）、非功能需求、5 项关键设计决策、SQLite 数据模型、REST + WS 接口协议、风险对策、验收标准
- `docs/02-实现计划.md` —— 9 个阶段（阶段0 骨架 → 阶段8 插件打包）、每阶段任务/验收清单、工作量汇总（约 14 人日）、测试策略、环境与运行方式、5 个待确认决策点

**关键技术决策（后续写代码须遵守）**
1. 终端 I/O 走 WebSocket **binary frame**，控制消息走 text JSON —— 避免 base64 的 33% 膨胀
2. 编码转换放在**服务端**（iconv-lite + StringDecoder 累积不完整多字节），前端始终按 UTF-8 处理
3. `Session`（持久化配置）与 `TerminalSession`（运行时标签）解耦；会话表只存 `credential_id`，凭据独立加密表
4. 背压：服务端累积 ≥64KB 时 `channel.pause()`，前端 ACK 后 `resume()`
5. 脚本沙箱用 `node:vm` + 白名单 API（**不用 vm2**，已停止维护且有逃逸漏洞）
6. 凭据加密：scrypt 派生主密钥（仅内存）+ AES-256-GCM；服务默认只绑 `127.0.0.1`

**锁定版本**：ssh2 1.17 / fastify 5.12 / better-sqlite3 13（要求 node ≥22）/ @xterm/xterm 6.0 / iconv-lite / zod / Vite 7 / Tailwind 4

- web：`terminal/{TerminalPane,useTerminalConnection,theme}`、`store/useTerminalStore.ts`、`components/{NewSessionDialog,TerminalTabs}.tsx`
- dev 工具：`packages/server/dev/mock-ssh-server.mjs`（含 `big`/`cols`/`gbk` 指令与 `MOCK_LEGACY=1` 老设备模拟）

**验证结果（全部实跑）**
- 服务端 E2E：**17/17**（健康/能力/探测/401/400/建终端/令牌鉴权/尺寸/中文/背压 4MB/静默恢复/exit/回收）
- 浏览器 E2E：**16/16**（puppeteer-core + 系统 Chrome，含真机诊断场景）
- 算法自动降级：legacy-only mock 下 modern 失败 → 自动切 legacy（group14-sha1 + ssh-rsa）全链路可用
- 真机 192.168.1.254：自动降级成功、指纹已记录、探测准确报出「认证通过但拒绝会话」

**关键实现决策（与计划文档的差异/细化）**
1. 背压改为**双信号**：客户端 ACK（xterm write 回调）+ WS `bufferedAmount`，任一超标即 pause；因为只靠 bufferedAmount 覆盖不了「浏览器收到但渲染不过来」
2. UTF-8 走**零拷贝直通**（不做解码再编码），只有 GBK/Big5 等才经 iconv 增量转码 —— 更快且天然无跨包乱码
3. SSH 连接在 **REST 阶段建立**（POST /api/terminals），认证失败/算法不兼容以标准 HTTP 状态码返回；WS 只负责附加渲染
4. 主机密钥把 `ssh-rsa` 排在 `ecdsa-sha2-nistp521` 之前（真机实测 ecdsa 在 ssh2 下签名校验失败）
5. 关闭标签必须显式 `DELETE /api/terminals/:id`，否则 SSH 连接会挂到空闲超时、占用远端 VTY

**遗留 / 后续**
- 前端 bundle 552KB（gzip 154KB），阶段 7 可做 xterm 动态 import 代码分割
- 标签状态不持久化（刷新后丢失，服务端超时回收孤儿终端）—— 符合设计，持久化应做在阶段 2 的会话库
