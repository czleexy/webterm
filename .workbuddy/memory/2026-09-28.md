5. 跳板链每跳独立走算法降级与 TOFU 校验；链条任何一环失败即回收已建立的中间连接

## 阶段 2 E2E 跑通：修复两个阻断性 bug（提交 0a5b482）

前次被审批拦截的 E2E 这次跑通，过程中暴露并修掉两个各自独立的阻断缺陷。

**Bug 1 — 保险库恒 500（`security/vault.ts`）**
- 现象：`POST /api/vault/setup` 恒返回 500「保险库操作失败」，浏览器里无法设置主密码。
- 根因：`scryptSync(N=2^15, r=8)` 需 `128*N*r = 32MiB` 内存，**恰好等于** Node 默认 `maxmem`（32MiB）上限，抛 `ERR_CRYPTO_INVALID_SCRYPT_PARAMS`。该异常不是 `VaultError`，被路由的 `handleVaultError` 兜底成 500，且**不写日志**，所以看不到任何线索。
- 修复：显式传 `maxmem = 128*N*r*2`；把派生逻辑抽成模块级 `deriveKey()`，杜绝 setup/unlock 两处参数漂移；非 `VaultError` 异常改为 `request.log.error` 记录。
- 教训：该 bug 依赖 Node 版本（本机 dev 用 Node 26、E2E 用 Node 22），跨版本行为不同的加密参数必须显式给全。

**Bug 2 — mock 跳板转发永不生效（`dev/mock-ssh-server.mjs`）**
- 现象：三级跳 A→B→C 建终端时报「跳板机拒绝转发到 127.0.0.1:2223：Channel open failure」，reason=1；mock 端**完全没有** `direct-tcpip` 日志。
- 根因：**ssh2 服务端 emit 的事件名是 `'tcpip'`，不是协议层的通道类型名 `'direct-tcpip'`**（见 `ssh2/lib/server.js:608` — `listenerCount(this, 'tcpip')` + `this.emit('tcpip', ...)`）。mock 注册的名字对不上 → `listenerCount` 为 0 → 服务端自动拒绝。客户端 `forwardOut` 实现本身正确。
- 修复：mock 改注册 `client.on('tcpip', ...)`。

**验证**
- 阶段 2 端到端 **36/36 通过**（跳板三级跳、Ed25519+口令密钥登录、DB 密文校验、锁定/解锁 423/401、重启持久化、凭据引用保护）
- E2E 脚本增强：启动诊断输出 + `process.on('exit')` 兜底清理子进程（原先失败路径会留孤儿 mock 占端口）

**调试方法论（值得复用）**
- 面对「500 且无堆栈」：先给兜底分支加日志，再复现；不要猜。
- 「服务端没反应」类问题：先确认请求是否真的到达（在对方埋 `console.log`），再查两侧实现。本例正是靠「mock 日志里没有 direct-tcpip 一行」直接锁定是事件名问题。
- 读依赖库源码（`node_modules/ssh2/lib/server.js`）比读文档更快更准。

## 修复：首屏永久卡在「正在连接服务…」（提交 5ff0375）

用户报告打开页面只看到加载态，看不到「设置主密码」入口。

**根因（纯前端装配缺失）**
- 全项目**从未调用过 `useVaultStore.refresh()`**。`VaultGate` 的 `ready` 恒为 `false`，
  永久停在加载分支。App 里只有 `useLibraryStore.getState().refresh()`。
- 已修：App 挂载时拉一次保险库状态。
- 顺带加固：`refresh()` 失败时也置 `ready` 并记录 `error`（否则服务端不可达时同样无限加载）；
  `VaultGate` 新增「无法连接服务端」分支 —— **若不拦下 `status === null`，后续 `isSetup = !status?.initialized`
  会算出 `true`，诱导用户重新设置主密码从而覆盖已有保险库**。

**为什么阶段 2 没发现**：阶段 2 只做了 typecheck / build / 最小冒烟 + **后端** E2E（脚本直接打 REST 与 WS）。
纯前端装配缺失在 API 层完全不可见。**教训：接口全绿 ≠ 应用可用，前端必须过一遍浏览器。**

**新增验证资产：`data/tmp/e2e-browser-p2.mjs`（两阶段）**
- `PHASE=setup`（18 项）：门禁渲染 → 设置主密码 → 内联新建凭据 → 建会话 → 单击连终端 →
  `echo` 回显 → 刷新后仍在主界面
- `PHASE=unlock`（9 项）：服务端重启后要求解锁 → 错误密码被拒 → 正确解锁 → 会话与凭据保留
- 目标实例通过 `WEBTERM_WEB` 指定，**用独立实例（8097，NODE_ENV=production 由服务端托管前端）跑，
  不污染开发用的 8080**
- 两个必须知道的写法：
  - 给 React 受控组件填值必须走**原生 setter + `input` 事件**，直接改 `value` 不生效
  - xterm 的 `.xterm-helper-textarea` 是透明浮层，`page.click()` 会报 not clickable，
    要用 `evaluate(() => el.focus())`
- 断言注意：**刷新浏览器不会要求解锁**（解锁态在服务端进程内存里），只有重启服务端才会；
  错误密码解锁的 401 属预期业务响应，统计 console error 时要排除

**一个被自己写错的断言纠正**：凭据**不在侧边栏展示**，只在会话对话框的凭据下拉里；
验证凭据是否拉回需打开编辑会话对话框。
