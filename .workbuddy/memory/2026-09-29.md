### 本次排障的关键教训

1. **mock 只认 LF、xterm 回车只发 CR** —— 5 个「终端无响应」断言全挂在同一个根因上。修法是让 mock 像 telnetd 一样 CR/LF 都认（CRLF 算一次换行）。产品侧保持**原样透传**，这是对的：真实设备/telnetd 都接受 CR。
2. **文案断言会撞车**：Telnet 的提示段落里也写了「跳板链」三个字，`hasText('跳板链')` 必然误判 —— 改断言「+ 添加一跳」这种 UI 专属文案。
3. **zod `.default()` 会补字段**：Telnet 记录读回来会带 `jumpChain: []`（甚至 `legacyCompat: 'auto'`），断言应写「无凭据 + 跳板链为空」而不是「字段不存在」。
4. **`data-testid` 是模板字面量**（`` `protocol-${value}` ``），grep 字面量 `protocol-telnet` 会查到 0 —— 别用 grep 结果否定已经跑通的测试。
5. E2E 里读 xterm 只能读到**视口行**（`.xterm-rows`），`big 128` 之类的大输出会把早先内容滚出视口 —— 断言要紧跟在对应命令之后做。

### 排障教训（阶段 6）

1. **⚠️ `env -u CODEBUDDY_SAFE_DELETE_BULK_*` 现在会让 node 进程静默退出**（exit 0、无任何输出、1~3 秒死）——上面阶段 5 的放行写法已失效/有害。e2e-browser-tunnel 带 `env -u` 连挂 3 次（0 输出），去掉后一次 98/98 通过。**以后不要再加 env -u**；撞批量删除保护时优先考虑手动清 WORK 目录再跑。
2. 测试脚本轮询「运行记录」时必须等 `phase !== 'running'`——记录在运行**开始**时就落库，拿到的是无 result 的记录。
3. 首个会话建立后欢迎页消失，`data-testid="new-tab"`（标签栏 + 按钮）是后续建连的唯一入口——UI 自动化要双入口兜底。
4. `display:none` 面板里的 xterm 读不到（渲染器不更新），`innerText` 对隐藏元素恒为 `''`——断言前先把标签切到前台，读取用 `textContent`。
5. 「停用后不再命中」类负断言要比对**出现次数**（回滚缓冲里还有旧输出，`includes` 必然误判）。
6. CodeMirror 的 `HighlightStyle` 从 `@codemirror/language` 导入，`@lezer/highlight` 里没有。
7. 受控 `<select>` 的 E2E 赋值要扩到 `HTMLSelectElement.prototype` 并同时派发 `change`。
