### 本轮修出的三个真 bug

1. **脱敏被传输分片切断**（安全问题）：逐 chunk 做脱敏时 `password=secret123` 会被切成 `password=sec` + `ret123`，两半都不匹配 `\S+`，**敏感内容原样落盘**。改为先按行缓冲、整行到齐再脱敏，`\n` 前的残余留在 `pendingLine`。E2E 有专门用例（把敏感串故意放在分片边界上）。
2. **`serialize()` ≠ HTML**：`SerializeAddon.serialize()` 返回的是 **ANSI 文本**，HTML 回放必须用 `serializeAsHTML()`。首版用错，快照里全是原始 `\x1b[31m` 字节，浏览器打开一片黑白。由「取计算样式 RGB 通道」的断言抓出。
3. **回放页底色写死深色**：浅色主题下终端本身是白底（Solarized Light），快照外壳却把 `body{background:#101418}` 写死 → 回放页成「白色终端块浮在深色页面上」。改为从 `term.options.theme` 取底色/前景色；断言从「不是全透明」这种弱检查换成「等于终端主题底色」（`rgb(251,251,250)`）。

另有性能修复：**写入批量合并**（256 KB 或 200 ms）。原先一行一次 `appendFile`，21 MB 输出要近 30 万次系统调用，慢到 E2E 跑不完。

### 排障教训（可复用）

- ⚠️ **终端有应用层背压**（`unackedBytes`，高水位 64 KB）。WS 客户端**必须周期性回 `ack`**，否则远端输出在 64 KB 处**永久暂停** —— 症状是「输出卡在 64 KB」。写 E2E 收集器时每收 32 KB 回一次 ack。
- ⚠️ **会话弹窗的凭据下拉读的是前端 store 快照**，而 store 只在「解锁」与「删除节点/凭据」后刷新。用 API 在解锁之后新建凭据，下拉里看不到 → 表现为「选择凭据假通过、保存时校验失败、弹窗不关」。E2E 里建完凭据要 **`page.reload()`** 一次（解锁态在服务端进程内存，刷新浏览器不会要求重新解锁）。
- ⚠️ **`setSelect` 对不存在的 option 赋值会被浏览器静默置空**。给 React 受控 select 填值前必须先等该 option 出现，并把返回值改成 `el.value === v`，否则「填写成功」是假的。
- ⚠️ **`typeLine` 只作用于 `[data-active="true"]` 的终端**。多标签场景下要先按标题点击工作区标签（`[role="tab"]`）切回目标终端，否则命令打进了别的标签，而断言仍会通过（因为输出确实出现在某个终端里）。
- ⚠️ **截图要拍对页面**：回放验证用的是独立的 `replayPage`，`page.screenshot()` 拍到的是主应用界面。截图必须显式指定 `replayPage.screenshot()`。
- ⚠️ **文档里的 `env -u CODEBUDDY_SAFE_DELETE_BULK_*` 放行写法已失效且有害**（会让 node 静默退出）。本次把 `docs/03-测试指南.md` 中 5 处相关引用全部改掉，并新增一条 FAQ「E2E 脚本一运行就没了（exit 0、无输出、1~3 秒退出）」。

### 实现要点（见 docs/02-实现计划.md 的 18 条实现记录）

- **分屏不用 react-resizable-panels**（库装了又卸，零新增依赖）：它的 `PanelGroup > Panel > 内容` 层级切布局时会换终端的父节点 → React 卸载重建 → WS 重连 → **服务端再建一条 SSH 连接**。改为 CSS Grid 自绘，所有终端恒为同一网格容器的直接子元素，只改 `grid-area`。
- 十字分隔条**拆四段**：竖条贯穿整列、横条贯穿整行会在正中重叠，横条压在上面 → 「拖竖条改列宽」变成「改行高」。
- `registerDecoration` 必须 `allowProposedApi: true`，否则**静默 0 结果**（异常被搜索的 catch 吞掉）。
- 高亮要**单独扫光标所在行**：不换行的回显正写在这一行上，当它「已定型」跳过就永远扫不到。
- 搜索计数被 `highlightLimit`(2000) 截断，界面显示 `2000+`。
- 快捷键用 `event.code`（物理键位）+ **捕获阶段**监听（冒泡时远端已收到按键）；`Ctrl+T/W/Tab` 网页拦不住，默认绑定避开并给出原因文案。

### 两条与「缓冲」有关的新认知（重要）

1. ⚠️ **分屏会让滚动缓冲顶部被裁掉**：pane 变窄 → xterm 对滚动缓冲**重排（reflow）**，72 字符长行重新折行、行数几乎翻倍，越过 scrollback 上限就丢最老的行。**不是终端被重建**（用 `.xterm` 内部节点身份验证过）。**别拿缓冲区顶部内容当「缓冲还在不在」的探针** —— 那会得到一个像「终端被重建了」的假失败。
2. ⚠️ **折行缓冲下搜索的滚动落点会偏**（已知限制，未修）：`resultIndex/count` 都正确（找到了），但视口落在命中行下方约半屏（实测差 ~20 行）。未折行缓冲里定位精确（254 ms 一次到位）。定位到 xterm SearchAddon 按「折行段偏移」换算目标行的内部偏差。

### E2E 断言写法教训

- ⚠️ **搜索单结果会让「上下跳转」断言退化成恒假/恒真**：要用**大量重复**的关键字（如 `big` 输出里的 `vwxyz01234`），断言 index 前进/后退。
- ⚠️ **正则搜索不能拿模式串当「已滚到」的判据**：`shown.includes('PHASE8-ANCHOR-[A-Z]+')` 永远为假。`findAndReveal` 要把 needle 与 expectText 分开。
- ⚠️ **「视口出现命中」与「计数回流到 React」不是同一拍**：命中后要再收敛 1.5s 读计数，否则读到上一轮的值。
- ⚠️ **Chrome 不会为单次 `click({clickCount:2})` 合成 dblclick**：双击必须发两次完整 down/up（第二次 `clickCount:2`）。首版的双击复位断言因此**假通过**（前一步拖拽失败、比例本来就是 0.5）。
- ⚠️ **`page.mouse.click` 前要确认落点没被别的元素盖住**：四宫格十字若不拆段，按竖条中心实际命中的是横条。
- ⚠️ CDP `Browser.setPermission` 才能精确控制通知权限（无头浏览器默认 denied），走完「未申请 → 请求授权 → 已授权」需要先把它设为 `default`。

### 阶段 9 关键实现约束（改代码前必读）

- **插件动作必须同步返回**（触发器引擎跑在输出流上）；异步收尾走插件日志 + 全局事件通道
- **`node:vm` 不是安全沙箱**：只换 API 面限定 / 生命周期 / 崩溃隔离；`permissions` 只做界面提示不做拦截
- **配置热更新共享同一 config 对象引用**（就地改），不重载插件；入库前 `normalizeOverrides`（类型转换+钳制+丢未知键）
- **输出订阅全局一份**：`wantsOutput()` 按需订阅，避免 N 插件 × M 会话爆炸；`replace()` 后必须 `syncOutputSubscriptions()`
- **`TRIGGER_ACTION_TYPES` 是落库白名单**：漏加的症状是「规则能存、接口能查、运行时什么都不做且不报错」
- 发布包布局：共享包摊平到 `vendor/shared` 并声明 `file:` 依赖 + `bundledDependencies`（直接写 node_modules 会被 npm install 清掉）
- `pino-pretty` 是 devDependency，发布形态用 `createRequire` 探测后退化（解析不到会带走进程）
- `bin/webterm.mjs` 动态 import 必须 `pathToFileURL()`（Windows 盘符）
