## 1. 产品定位

### 1.1 一句话定义

一个**运行在本机的 Node.js 服务**，通过浏览器提供 SecureCRT 级别的 SSH 终端能力：多标签终端、会话管理、SFTP 文件传输、端口转发、脚本自动化、会话日志审计。

### 1.2 与 SecureCRT 的差异（设计取舍）

| 维度 | SecureCRT | WebTerm | 说明 |
| --- | --- | --- | --- |
| 交付形态 | 桌面原生客户端 | 本地服务 + 浏览器 | 免安装、跨平台、可远程访问、易二次开发 |
| 终端渲染 | 原生 VT 引擎 | xterm.js（VT100/xterm-256color 完整实现） | 渲染能力对齐，WebGL 加速 |
| 脚本 | VBScript / Python / JS | JavaScript 沙箱（Node vm） | 更贴近 Node 生态 |
| 多端协同 | 无 | 支持同一会话多浏览器同时观看 | B/S 架构天然优势，等价于 tmux attach |
| 免安装部署 | 需逐台安装 | 服务器装一次，任意浏览器访问 | 运维场景优势明显 |

### 1.3 目标用户与核心场景

- **运维工程师**：批量管理几十到几百台 Linux 主机，需要会话分组、批量执行、日志留痕
- **后端开发**：频繁跳板机登录、本地代码与远程文件互传、隧道调试数据库
- **测试/交付**：需要把连接配置一键分享给同事（导出会话文件）

### 2.3 技术选型

| 层次 | 选型 | 版本 | 选择理由 |
| --- | --- | --- | --- |
| 运行时 | Node.js | ≥ 22 LTS | better-sqlite3 13 要求 node ≥ 22；原生 WebSocket、fetch |
| 语言 | TypeScript | 5.x | 前后端共享类型定义（`packages/shared`） |
| 后端框架 | Fastify | 5.12 | 性能优于 Express，内置 JSON Schema 校验，插件生态成熟 |
| WebSocket | ws | 8.x | 与 Fastify 共用同一 HTTP Server，无需额外端口 |
| SSH 协议 | ssh2 | 1.17 | 纯 JS 实现，无原生编译依赖；同时覆盖 shell/exec/sftp/forward |
| 数据库 | better-sqlite3 | 13.x | 同步 API，单机场景性能最优，零运维 |
| 加密 | node:crypto (scrypt + AES-256-GCM) | 内置 | 不引入额外依赖，标准算法 |
| 编码转换 | iconv-lite | 最新 | 支持 GBK/GB18030/Big5，兼容国产系统 |
| 参数校验 | zod | 4.x | 前后端共享 Schema |
| 前端构建 | Vite | 7.x | 启动快，产物直接由后端静态托管 |
| UI | React 18 + Tailwind CSS 4 | — | 组件化 + 原子化样式 |
| 终端 | @xterm/xterm | 6.0 | 事实标准，addon 生态完整（fit/search/webgl/links） |
| 状态管理 | Zustand | 5.x | 轻量，适合标签/会话这类高频局部状态 |
| 数据请求 | TanStack Query | 5.x | 缓存与失效策略开箱即用 |
| 组件原语 | Radix UI | 最新 | 无样式、可访问性好，风格自控 |
| 分屏布局 | react-resizable-panels | 最新 | 拖拽分栏，实现分屏终端 |

**不选用的方案及原因**

- ❌ `node-pty`：本项目是 SSH 远程终端，不需要本地 PTY；且该库需原生编译
- ❌ Electron：与已确认的「本地 Web 服务」形态冲突，且包体大
- ❌ `vm2`：已停止维护且存在逃逸漏洞，改用 `node:vm` + 受限 API 白名单

> F5.1 ~ F5.7 **已交付**（2026-09-29）。实现口径：
>
> | 编号 | 实现要点与取舍 |
> | --- | --- |
> | F5.1 | 匹配与自动应答都在**服务端**完成 —— 浏览器没打开、标签在后台，该答的仍然答得上。匹配按**行**进行（跨 chunk 切分不会漏），支持正则与纯文本两种模式；修饰符白名单只留 `i/m/s/u`，**排除 `g`/`y`** 以避免 `lastIndex` 带来的「时灵时不灵」。动作为自动应答、高亮标色、浏览器通知、记录标签、执行脚本五类。作用域分全局与会话级；命中后终端里追加一行提示，因为「答了但用户不知道」比「没答」更危险 |
> | F5.2 | 按钮栏长在**终端工具栏下方**（针对「这个会话」的动作不该先去面板选目标）。步骤为顺序语义：`send` → `delayMs`（无条件等）→ `expect`（等到为止、有上限），三者不合并 |
> | F5.3 | `node:vm` + `createContext` 白名单注入 `session` / `sftp` / `log` / `console` / `sleep` / `target` / `params`；**没有 `require`/`process`/`fs`，也没有 `eval` 与 `new Function`**。可终止性靠 **worker + `terminate()`** 兜底：`vm` 的 `timeout` 只覆盖第一段同步执行，`await` 之后进的死循环必须靠终止 worker 才能收场。编辑器为 CodeMirror 6，内置 API 补全与文档同源 |
> | F5.4 | 三种绑定齐备：手动运行、会话建立后自动运行（`runOnConnect`）、被触发器动作调用。删除脚本会返回**被引用次数**并提示哪些绑定会失效；已失效的引用在规则列表上显示明确的 `lastError`，不静默消失 |
> | F5.5 | 目标集在**开启的那一刻锁定**，新开的标签不会自动加入（避免「悄悄多了一个受害者」）；输入不去抖、不合并（时序敏感）；警示条常驻工作区顶部并回显接收方数量，**Alt+B** 一键停止 |
> | F5.6 | 优先复用**已登录**的 SSH 连接另开 exec 通道（不占新 VTY 线路），也可从会话库独立建连。固定并发度任务池 + 单目标超时；stdout 与 stderr 分栏。**只支持 SSH** —— 要拿退出码就必须有 exec 通道，Telnet 目标被明确拒绝而不是给一个不可信的成功 |
> | F5.7 | CSV 带 UTF-8 BOM（否则中文版 Excel 打开乱码），换行 `\r\n` |
>
> F5.8（宏录制与回放）**未交付**：录制需要把「人在终端里的原始输入」与「程序输出」做时序对齐，在不可控的远端交互下容易产生看似能跑、换个环境就崩的宏。当前用「显式配置步骤」替代，用户能清楚看到每一步在等什么。验收记录见 `docs/02-实现计划.md` 阶段 6 一节。

> F6.1 ~ F6.6 **已交付**（2026-09-30）。实现口径：
>
> | 编号 | 实现要点与取舍 |
> | --- | --- |
> | F6.1 | 三种格式都做。纯文本 / 带时间戳由服务端在**会话输出流**上流式追加；HTML 由**前端**用 `@xterm/addon-serialize` 的 `serializeAsHTML()` 定期序列化整份缓冲后分片上传（服务端不引入 xterm），因此只有浏览器标签打开着时才有 HTML 快照 |
> | F6.2 | 归档路径实际是 `logs/{清洗后的会话名}-{sessionId 短哈希}/{YYYY-MM-DD}.log`。加短哈希是因为只按会话名建目录会让**两个不同主机上的同名会话互相覆盖**。没有做「追加 / 覆盖」开关：按天分文件后，同一天内天然就是追加语义，跨天不覆盖 —— 一个多余的开关只会多一个配错的地方。会话改名后目录**不漂移**（映射单独持久化），否则历史日志会突然「换主人」 |
> | F6.3 | 预览**不读全文**：首次访问时按字节扫一遍 `0x0A` 建行偏移索引，之后任意窗口 O(1) `seek + read`。实测 27.99 万行 / 21 MB 的文件跳转到第 10 万行 **2 ms**。索引按 `size + mtime` 失效，LRU 缓存 8 个文件 |
> | F6.4 | 实际记了八类事件：`connect` / `disconnect` / `upload` / `download` / `macro_run` / `script_run` / `log_delete` / `settings_change`，全部带客户端 IP。存储的是**入库前就拼好的整句**（`用户从 127.0.0.1 上传了 a.zip（2.4 MB）`）而不是结构化字段留给前端再拼 —— 审计的价值在事后能看懂 |
> | F6.5 | 规则可配（最多 32 条，可逐条启停，编辑时就地校验正则）。**关键实现约束：必须按行对齐后再脱敏**。逐 chunk 脱敏会被传输分片切断正则（`password=sec` + `ret123` 两片都不匹配 `\S+`），敏感内容原样落盘。另外 HTML 快照**不做脱敏**（字节级忠实回放，替换文本会破坏标记结构把颜色改坏）—— 这条边界在设置页与文档里都写明了 |
> | F6.6 | 单文件超 20 MB 切分为 `{日期}.part{n}.log`；保留天数 1 ~ 3650 天（默认 30），定时清理 + **改完设置立即清一轮**（等下一个整点的话，用户收紧保留期后看到的还是旧状态） |
>
> 附带一处与文档原描述不同的取舍：HTML 快照落地为 **`.html` 扩展名**（而非 F6.2 里的 `.log`），因为浏览器只对 `.html` 做「打开即渲染」，`.log` 会被当纯文本下载，验收条件「HTML 日志在浏览器打开颜色正确」依赖这一点。

## 5. 关键设计决策

### 5.1 终端数据用二进制帧，不用 JSON

**问题**：WebSocket 传 JSON 字符串需 base64 编码二进制数据，体积膨胀 33%，且序列化耗时。

**决策**：终端 I/O 走 WebSocket **binary frame**（`ArrayBuffer`），前端 `term.write(new Uint8Array(buf))`。
控制类消息（resize/attach/status）走 text frame JSON。通过首字节或帧类型区分。

### 5.2 编码转换放在服务端

浏览器 `TextDecoder` 对 GBK 支持受限于 ICU 构建，不可靠。
**决策**：SSH 通道输出先由服务端 `iconv-lite` 解码为 UTF-8 字符串流再下发；用户输入反向转码。前端始终按 UTF-8 处理。

### 5.3 会话与标签解耦

`Session`（连接配置，持久化）与 `TerminalSession`（运行时标签，内存）分离。
一个 Session 可开多个标签；标签关闭不删配置。`TerminalSession` 持有 ssh2 `Client`、shell `Channel`、编码器、日志写入器、触发器绑定。

### 5.4 背压控制

SSH channel 数据到达速度可能远超浏览器消费速度（如 `cat` 大文件）。
**决策**：服务端按累积阈值（如 64 KB）暂停 `channel.pause()`，前端消费后回 ACK（或使用 `ws` 的 `bufferedAmount` 水位），恢复 `resume()`。避免 Node 侧内存无限增长。

### 5.5 凭据引用而非内嵌

会话表不存密码字段，只存 `credential_id`。多会话共用同一凭据，改密码只需改一处。

## 6. 数据模型

```sql
-- 文件夹（会话分组，支持无限层级）
CREATE TABLE folders (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  parent_id   INTEGER REFERENCES folders(id) ON DELETE CASCADE,
  name        TEXT NOT NULL,
  sort_order  INTEGER DEFAULT 0
);

-- 凭据（加密存储）
CREATE TABLE credentials (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  name        TEXT NOT NULL UNIQUE,
  type        TEXT NOT NULL,           -- password | private_key | passphrase | agent
  cipher_text TEXT NOT NULL,           -- AES-256-GCM 密文（base64）
  iv          TEXT NOT NULL,
  auth_tag    TEXT NOT NULL,
  key_path    TEXT,                    -- type=private_key 时指向 data/keys/*
  created_at  INTEGER NOT NULL
);

-- 会话配置
CREATE TABLE sessions (
  id             INTEGER PRIMARY KEY AUTOINCREMENT,
  folder_id      INTEGER REFERENCES folders(id) ON DELETE SET NULL,
  name           TEXT NOT NULL,
  protocol       TEXT NOT NULL DEFAULT 'ssh',   -- ssh | telnet | serial | raw
  host           TEXT,
  port           INTEGER DEFAULT 22,
  username       TEXT,
  auth_type      TEXT DEFAULT 'password',       -- password | publickey | keyboard | agent | combo
  credential_id  INTEGER REFERENCES credentials(id) ON DELETE SET NULL,
  encoding       TEXT DEFAULT 'utf8',
  term_type      TEXT DEFAULT 'xterm-256color',
  keepalive      INTEGER DEFAULT 30,            -- 秒，0 为禁用
  proxy_chain    TEXT,                          -- JSON：跳板机链 [{host,port,user,credentialId}]
  options_json   TEXT,                          -- 其他扩展项（颜色、日志开关等）
  sort_order     INTEGER DEFAULT 0,
  last_used_at   INTEGER,
  created_at     INTEGER NOT NULL,
  updated_at     INTEGER NOT NULL
);

-- 主机指纹
CREATE TABLE known_hosts (
  host        TEXT NOT NULL,
  port        INTEGER NOT NULL,
  key_type    TEXT NOT NULL,
  fingerprint TEXT NOT NULL,
  added_at    INTEGER NOT NULL,
  PRIMARY KEY (host, port, key_type)
);

-- 端口转发
CREATE TABLE port_forwards (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  session_id   INTEGER NOT NULL REFERENCES sessions(id) ON DELETE CASCADE,
  name         TEXT,
  type         TEXT NOT NULL,          -- local | remote | dynamic
  bind_host    TEXT DEFAULT '127.0.0.1',
  bind_port    INTEGER NOT NULL,
  target_host  TEXT,
  target_port  INTEGER,
  auto_start   INTEGER DEFAULT 0,
  enabled      INTEGER DEFAULT 1
);

-- 触发器
CREATE TABLE triggers (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  session_id   INTEGER REFERENCES sessions(id) ON DELETE CASCADE,  -- NULL = 全局
  name         TEXT NOT NULL,
  pattern      TEXT NOT NULL,
  is_regex     INTEGER DEFAULT 1,
  action_type  TEXT NOT NULL,          -- reply | highlight | notify | script | log_only
  action_value TEXT,
  enabled      INTEGER DEFAULT 1,
  sort_order   INTEGER DEFAULT 0
);

-- 脚本
CREATE TABLE scripts (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  name        TEXT NOT NULL,
  description TEXT,
  code        TEXT NOT NULL,
  kind        TEXT DEFAULT 'manual',   -- manual | login | trigger
  updated_at  INTEGER NOT NULL
);

-- 会话日志索引
CREATE TABLE session_logs (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  session_id  INTEGER REFERENCES sessions(id) ON DELETE SET NULL,
  session_name TEXT NOT NULL,
  file_path   TEXT NOT NULL,
  format      TEXT NOT NULL,
  started_at  INTEGER NOT NULL,
  ended_at    INTEGER,
  size_bytes  INTEGER DEFAULT 0
);

-- 审计日志
CREATE TABLE audit_log (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  ts         INTEGER NOT NULL,
  session_id INTEGER,
  action     TEXT NOT NULL,            -- connect | disconnect | upload | download | script_run
  detail     TEXT,
  client_ip  TEXT
);

-- 全局设置
CREATE TABLE settings (
  key   TEXT PRIMARY KEY,
  value TEXT NOT NULL
);
```

## 8. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 浏览器跨域/Origin 限制导致 WS 拒绝 | 无法连接 | 服务端校验 Origin 白名单，并允许 `127.0.0.1`/`localhost` |
| 终端大输出导致页面卡死 | 用户体验崩塌 | 服务端背压 + 前端 xterm write 批量缓冲（requestAnimationFrame 合帧） |
| GBK 编码下中文字符被截断在多字节中间 | 乱码 | 服务端使用 `StringDecoder` 累积不完整字节，不做逐块独立解码 |
| ssh2 对部分老旧算法（ssh-rsa/diffie-hellman-group1-sha1）默认禁用 | 连不上老设备 | 会话级「兼容模式」开关，显式放开旧算法 |
| 串口/Telnet 协议实现复杂度高 | 拖期 | 优先级排在 SSH 之后，接口先用插件化占位 |
| 主密码忘记后凭据不可恢复 | 数据丢失 | 首次设置时強提示；提供「导出明文配置」的一次性逃生通道 |

## 9. 验收标准（v1.0）

1. 能在浏览器中同时打开 ≥ 10 个 SSH 终端标签，操作流畅无卡顿
2. 密码与 Ed25519 密钥两种认证方式均可成功登录，且密码在数据库中为密文
3. 通过 SFTP 上传/下载 ≥ 100 MB 文件成功，进度准确，中断后可续传
4. `-L` / `-R` / `-D` 三种隧道均可正常建立并转发流量
5. 触发器命中后能自动应答指定内容，且规则可持久化
6. 会话日志按日期归档，HTML 格式日志可还原颜色并正常打开
7. 断开网络 30 秒后恢复，客户端自动重连并恢复终端尺寸
8. 服务重启后，所有会话配置、触发器、脚本完整保留
