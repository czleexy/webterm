## 一、总体实施策略

### 1.1 分层交付原则

不按「前端做完再做后端」的瀑布方式推进，而是**按功能纵切**：每个阶段打通一条从浏览器到目标主机的完整链路，交付一个可运行、可验证的版本。

```
阶段1 骨架        ██
阶段2 终端连通     ██████        ← 第一个可用里程碑（能连上主机敲命令）
阶段3 会话管理     ████████      ← 第二个里程碑（配置可保存、多标签、密钥登录）
阶段4 SFTP       ████████      ← 第三个里程碑（文件传输可用）
阶段5 隧道        █████         ← 第四个里程碑（端口转发可用）
阶段6 自动化       ███████       ← 第五个里程碑（触发器/脚本/批量）
阶段7 日志审计     ████
阶段8 体验打磨     ██████
阶段9 插件与打包   █████
```

**关键约束：阶段 1–3 完成前，不启动阶段 6 及以后的任何工作。** 早期优先保证主干链路稳固。

### 1.2 每个阶段的固定动作

```
写代码 → 类型检查(tsc --noEmit) → 构建(vite build) → 手动冒烟 → 提交
```

任一步失败，不允许进入下一阶段。

### 阶段 1：终端主干打通（1.5 天）★ 核心里程碑

**目标**：在浏览器里连上一台 Linux 主机，能正常敲命令、跑 vim/htop、窗口自适应。

**这是全项目风险最高的阶段**（WebSocket 双工 + PTY 尺寸 + 背压 + 编码），必须做扎实。

| 任务 | 关键实现点 |
| --- | --- |
| `packages/shared` 定义 WS 消息类型（zod schema + TS 类型） | 前后端共用，避免协议漂移 |
| `SshConnection` 封装 | `ssh2.Client` 连接、hostVerifier、readyTimeout、keepaliveInterval、连接错误码归一化 |
| `TerminalSession` 运行时对象 | 持有 client / stream / encoder / decoder / 背压水位 |
| Fastify WebSocket 网关 | 路由 `/ws`，握手校验 token 与 Origin，按 tabId 路由消息 |
| 二进制帧处理 | 终端输出 `ws.send(Buffer)` 走 binary；控制消息走 text JSON |
| 编码层 `encoding.ts` | `iconv-lite` + `StringDecoder` 累积不完整多字节，避免中文被切断 |
| 背压机制 | 服务端累积 ≥ 64KB 时 `stream.pause()`，收到前端 `ack` 后 `resume()` |
| 前端 `TerminalManager` | 每个 tabId 一个 xterm 实例，`FitAddon`、`WebglAddon`、resize 防抖上报 |
| 前端输出合帧 | 累积输出用 `requestAnimationFrame` 批量 `term.write()`，避免高频写渲染卡死 |
| 前端断线重连 | WS 指数退避重连 + `attach(lastSeq)` 请求补发 |

**验收清单**
- [ ] 连接 CentOS/Ubuntu 主机，密码登录成功
- [ ] `ls -al`、`vim`、`htop`、`top` 显示正常（备用屏正常）
- [ ] 中文输出不乱码，`echo 中文` 输入正常
- [ ] 拖动浏览器窗口，远程 `stty size` 输出的行列数同步变化
- [ ] `cat /dev/urandom | base64` 持续输出 10 秒，页面不卡死、后端内存不飙升
- [ ] 拔网线 30 秒后插回，客户端自动重连

### 阶段 2：会话管理与持久化（1.5 天）★ 里程碑

**目标**：会话可保存、可分组、可多标签并行、支持密钥登录。

| 任务 | 关键实现点 |
| --- | --- |
| SQLite 建表与迁移 | `better-sqlite3`，开启 WAL，`user_version` 做版本迁移 |
| `crypto.ts` | scrypt 派生主密钥（N=2^15）+ AES-256-GCM 加密凭据；密钥仅存内存 |
| 首次启动引导 | 未设主密码则强制设置页；已初始化则登录解锁 |
| 凭据 CRUD | 读接口永不返回明文，只返回 `{id, name, type}` |
| 会话/文件夹 CRUD REST | zod 校验入参，DAO 层参数绑定防注入 |
| 会话树 UI | Radix + dnd 拖拽排序，右键菜单（连接/编辑/复制/删除/新建子文件夹） |
| 会话编辑弹窗 | 分组表单（基本/认证/终端/日志/隧道），认证方式联动切换字段 |
| 多标签 | 标签栏 + 标签状态灯（连接中/已连/断开），中间件管理 xterm 实例生命周期 |
| 密钥认证 | 支持 RSA/ECDSA/Ed25519；私钥文件导入到 `data/keys`，私钥口令加密存储 |
| 键盘交互认证 | `keyboard-interactive` 事件 → 前端弹 OTP 输入框 |
| known_hosts | `hostVerifier` 回调 → 未信任时前端弹指纹确认卡片 → 记忆 |
| 跳板机 ProxyJump | 递归建立连接链，中间跳用 `forwardOut` 打通到下一跳 |
| 快捷连接栏 | 顶部输入 `user@host:port` 即连，不落库 |

**验收清单**
- [ ] 新建会话 → 重启服务 → 会话仍在
- [ ] 凭据在 DB 中为密文（直接查库验证看不到明文密码）
- [ ] 同时开 8 个标签连不同主机，切换流畅
- [ ] Ed25519 密钥 + 私钥口令登录成功
- [ ] 跳板机 A→B→C 三级跳转连上 C
- [ ] 首次连接弹指纹确认，二次连接不再弹，指纹被人为改动时告警

### 阶段 3：SFTP 文件传输（2 天）★ 里程碑

| 任务 | 关键实现点 |
| --- | --- |
| `SftpService` | 复用同一 ssh2 连接的 `sftp()` 通道，懒创建、断线重建 |
| 目录列举 | `readdir` → 排序（目录优先）、过滤隐藏文件开关、软链接标记 |
| 传输队列 | 服务端任务队列，状态机 `pending→running→paused→done/failed`，事件经 WS 推送 |
| 上传 | `@fastify/multipart` 接收流 → `createWriteStream(remote, {flags, mode})`；支持指定 offset 续传 |
| 下载 | `createReadStream(remote, {start})` → 响应流；支持 HTTP Range，浏览器原生断点续传 |
| 并发控制 | 默认 3 并发，可配；同目录同文件串行化 |
| 目录递归传输 | 递归遍历 + 自动 `mkdir -p`，保持相对路径结构 |
| 文件操作 | mkdir / rename / chmod（八进制）/ delete（递归二次确认）/ touch |
| 双栏 UI | 左侧本地（受限根目录，防 `..` 逃逸）、右侧远程；面包屑 + 路径输入框 |
| 拖拽交互 | HTML5 dragover/drop，跨栏拖拽=上传或下载，同栏拖拽=重命名/移动 |
| 传输面板 | 抽屉式面板，进度/速度/ETA，暂停/继续/取消/重试按钮 |
| 文本预览 | 远程文件前 N KB 拉取，判定文本类型后 CodeMirror 只读预览 |
| 远程编辑 | 下载到 `data/tmp` → 内置编辑器修改 → 保存回写 → 校验 mtime 防覆盖冲突 |

**验收清单**
- [ ] 上传 100 MB 文件成功，进度准确，取消后可重试
- [ ] 上传中途断网 → 重连后从断点续传（不重新传）
- [ ] 下载 500 MB 目录树成功，目录结构与权限保持
- [ ] chmod 644/755 修改后在服务器上 `ls -l` 验证生效
- [ ] 本地路径输入 `../../etc/passwd` 被拒绝

### 阶段 4：端口转发与隧道（1.5 天）

| 任务 | 关键实现点 |
| --- | --- |
| 本地转发 `-L` | `net.createServer` 监听 bind_port → `conn.forwardOut()` → pipe，双向错误处理 |
| 远程转发 `-R` | `client.forwardIn()` + `tcp connection` 事件 → 本地 `net.connect` 到 target |
| 动态转发 `-D` | 实现最小 SOCKS5 服务端（RFC 1928，仅 CONNECT + 无认证/用户名密码） |
| 生命周期 | 隧道随 Session 存活；会话断开时统一 `close()` 所有监听，释放端口 |
| 端口占用检测 | 启动前 `EADDRINUSE` 友好提示，提供「换端口重试」 |
| 管理面板 | 列表 + 内联开关 + 状态（运行中/已停止/错误）+ 活跃连接数 + 上下行字节统计 |
| 会话属性集成 | 会话编辑弹窗内嵌隧道配置，勾选随会话自动启动 |

**验收清单**
- [ ] `-L 13306:内网MySQL:3306`，本地用客户端成功连上内网库
- [ ] `-D 1080`，浏览器配置 SOCKS5 代理后可访问远程内网 HTTP 服务
- [ ] `-R` 反向隧道，从远程主机访问到本地服务
- [ ] 关闭会话后端口立即释放（`netstat` 验证）

## 四、测试策略

| 层级 | 范围 | 工具 |
| --- | --- | --- |
| 单元测试 | 编码转换、SOCKS5 协议解析、路径安全校验、crypto 加解密、触发器正则匹配 | Vitest |
| 集成测试 | 起一个本地 `ssh2.Server` 做被测目标，验证连接/认证/exec/sftp/forward 全链路 | Vitest + ssh2 Server |
| 端到端 | Playwright 驱动浏览器，跑「登录→新建会话→连接→输命令→上传文件」主流程 | Playwright |
| 压力/性能 | 并发 20 会话、大输出流、大文件传输 | 自建脚本 |

**必须覆盖的边界用例**
- 空输入、超长命令行、含 `\0` 的输入
- 编码：GBK 中文跨 chunk 边界
- SFTP：超大文件、权限不足、路径不存在、并发同名文件
- 认证失败、主机不可达、握手超时、指纹变更
- 脚本：死循环、抛异常、超时

## 五、开发环境与运行方式

```bash
# 安装依赖（根目录，workspaces 会一并安装子包）
npm install

# 开发模式：并行启动后端(8080) + 前端(5173，代理到后端)
npm run dev

# 类型检查
npm run typecheck

# 构建生产产物
npm run build

# 启动生产服务（默认 http://127.0.0.1:8080）
npm start

# 指定局域网访问（需显式开启并设置访问密码）
npm start -- --host 0.0.0.0 --port 8080
```

**环境变量**

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `WEBTERM_HOST` | `127.0.0.1` | 监听地址 |
| `WEBTERM_PORT` | `8080` | 监听端口 |
| `WEBTERM_DATA_DIR` | `./data` | 数据目录 |
| `WEBTERM_LOG_LEVEL` | `info` | 日志级别 |
| `WEBTERM_ALLOW_ORIGINS` | `http://localhost:5173,http://127.0.0.1:5173` | WS Origin 白名单 |
