## 一、总体实施策略

### 1.1 分层交付原则

不按「前端做完再做后端」的瀑布方式推进，而是**按功能纵切**：每个阶段打通一条从浏览器到目标主机的完整链路，交付一个可运行、可验证的版本。

```
阶段1 骨架        ██
阶段2 终端连通     ██████        ← 第一个可用里程碑（能连上主机敲命令）
阶段3 会话管理     ████████      ← 第二个里程碑（配置可保存、多标签、密钥登录）
阶段4 SFTP       ████████      ← 第三个里程碑（文件传输可用）
阶段5 隧道        █████         ← 第四个里程碑（端口转发可用）
阶段6 自动化       ███████       ← 第五个里程碑（触发器/脚本/批量）
阶段7 日志审计     ████
阶段8 体验打磨     ██████
阶段9 插件与打包   █████
```

**关键约束：阶段 1–4 完成前，不启动阶段 7 及以后的任何工作。** 早期优先保证主干链路稳固。

### 1.2 每个阶段的固定动作

```
写代码 → 类型检查(tsc --noEmit) → 构建(vite build) → 手动冒烟 → 提交
```

任一步失败，不允许进入下一阶段。

### 阶段 1：终端主干打通（1.5 天）★ 核心里程碑

**目标**：在浏览器里连上一台 Linux 主机，能正常敲命令、跑 vim/htop、窗口自适应。

**这是全项目风险最高的阶段**（WebSocket 双工 + PTY 尺寸 + 背压 + 编码），必须做扎实。

| 任务 | 关键实现点 |
| --- | --- |
| `packages/shared` 定义 WS 消息类型（zod schema + TS 类型） | 前后端共用，避免协议漂移 |
| `SshConnection` 封装 | `ssh2.Client` 连接、hostVerifier、readyTimeout、keepaliveInterval、连接错误码归一化 |
| `TerminalSession` 运行时对象 | 持有 client / stream / encoder / decoder / 背压水位 |
| Fastify WebSocket 网关 | 路由 `/ws`，握手校验 token 与 Origin，按 tabId 路由消息 |
| 二进制帧处理 | 终端输出 `ws.send(Buffer)` 走 binary；控制消息走 text JSON |
| 编码层 `encoding.ts` | `iconv-lite` + `StringDecoder` 累积不完整多字节，避免中文被切断 |
| 背压机制 | 服务端累积 ≥ 64KB 时 `stream.pause()`，收到前端 `ack` 后 `resume()` |
| 前端 `TerminalManager` | 每个 tabId 一个 xterm 实例，`FitAddon`、`WebglAddon`、resize 防抖上报 |
| 前端输出合帧 | 累积输出用 `requestAnimationFrame` 批量 `term.write()`，避免高频写渲染卡死 |
| 前端断线重连 | WS 指数退避重连 + `attach(lastSeq)` 请求补发 |

**验收清单**
- [ ] 连接 CentOS/Ubuntu 主机，密码登录成功
- [ ] `ls -al`、`vim`、`htop`、`top` 显示正常（备用屏正常）
- [ ] 中文输出不乱码，`echo 中文` 输入正常
- [ ] 拖动浏览器窗口，远程 `stty size` 输出的行列数同步变化
- [ ] `cat /dev/urandom | base64` 持续输出 10 秒，页面不卡死、后端内存不飙升
- [ ] 拔网线 30 秒后插回，客户端自动重连

### 阶段 4：Telnet 明文终端（插入交付，1 天）

> 原计划里没有这一段，是应需求「增加 telnet 功能，端口 23」插入的。
> 定位：不少老旧网络设备只开 23 端口、根本没配 SSH；工控 / 医疗 / 打印设备也有大量
> 只有 Telnet 的存量。让 WebTerm 能连它们，才算真正覆盖「老旧设备」这个主要场景。

| 任务 | 关键实现点 |
| --- | --- |
| 协议判别 | 共享层用**判别联合** `SshSessionConfig \| TelnetSessionConfig`（按 `protocol` 字段）而不是「一堆可选字段」—— 后者会让「telnet 却带了私钥」「ssh 却没带用户名」这类非法组合在类型上无法被发现 |
| 选项协商 | `TelnetNegotiator` 状态机（DATA / IAC / OPTION / SB_OPTION / SB_DATA / SB_IAC）逐字节解析，处理 DO/DONT/WILL/WONT 与子协商；对端拒绝后不再重复请求 |
| 能力上报 | `TERMINAL-TYPE` 上报 TERM、`NAWS` 上报窗口尺寸（resize 时重发），让设备端全屏程序（top / vi）排版正确 |
| 本地回显兜底 | 设备不声明 `WILL ECHO` 时由本端补回显（含退格 `\b \b`、不越界），解决「打字看不见」这个 Telnet 最常见的观感问题 |
| IAC 转义 | 收发两侧都做 `0xFF → FF FF` 转义，否则裸 0xFF 会被对端当成命令吃掉后续字节 |
| 传输层 | 裸 TCP `net.connect` + 建连超时；`terminals` 的 `TerminalSession` 抽象出双传输（SSH ClientChannel / TelnetTransport），背压、编码桥、标签生命周期完全复用 |
| 安全边界 | Telnet 无认证阶段 → **目标里不允许出现任何凭据字段**（口令在终端里交互输入）；会话库与 zod 校验显式拒绝 `credentialId` / `jumpChain`；界面常驻明文风险提示 |
| 能力裁剪 | Telnet 没有 SFTP 子系统 → 标签栏不提供「打开 SFTP」入口，服务端对 Telnet 会话开 SFTP 直接 400 `INVALID_CONFIG` |
| 探测 | `POST /api/sessions/probe` 对 Telnet 只验证「TCP 通不通 + 对端说不说话」，并把欢迎语（banner）带回来 —— 这是判断 23 端口后面到底是什么最直接的证据 |

**验收清单**
- [x] 与设备完成 DO/DONT/WILL/WONT 协商，拒绝的选项不再重复请求
- [x] `NAWS` 上报尺寸，窗口变化后设备侧看到的尺寸同步更新
- [x] 设备不声明回显时，本端回显让输入可见；设备声明回显时不重复回显
- [x] 裸 `0xFF` 双向转义，后续命令仍能正常解析
- [x] Telnet 会话不携带凭据与跳板链（前端不显示、服务端校验拒绝）
- [x] Telnet 标签上不出现 SFTP 入口，服务端拒绝对 Telnet 开会话
- [x] 服务端端到端 53/53、浏览器端到端 80/80 通过

### 阶段 5：端口转发与隧道（1.5 天）

> **已交付（2026-09-29）**。实现记录：
>
> | 任务 | 实现方式 |
> | --- | --- |
> | 本地转发 `-L` | `LocalForward`：`net.createServer` 监听 → `client.forwardOut()` → `bridge()` 双向管道（含背压）；建通道有 20 s 超时护栏 |
> | 远程转发 `-R` | `RemoteForward`：`client.forwardIn()` + 管理器级单监听 `'tcp connection'` 按 `destPort` 分发（未被认领的通道显式 reject）；`bindPort=0` 时用远端应答的真实端口做后续匹配；停止时 `unforwardIn` |
> | 动态转发 `-D` | `DynamicForward` + `Socks5Negotiator`：RFC 1928 增量状态机（仅 CONNECT、无认证），TCP 分包不会撕裂请求；BIND / UDP ASSOCIATE 回 REP 0x07，非法方法回 0xFF |
> | 公共基类 | `TunnelBase` 统一状态机（starting / active / stopped / error）、幂等 teardown、连接数与字节统计（带背压计数）；三类转发只差异在「在哪监听、如何拿到对端通道」 |
> | 生命周期 | 会话关闭时**先** `destroy()` 所有隧道（远端要在线才能撤 `tcpip-forward`）、**再**断 SSH 连接；顺序固化在 `TerminalSession.shutdown()` 与 `TerminalManager.close()` |
> | 端口占用 | errno 分类：`EADDRINUSE` → 409 `PORT_IN_USE` + 换端口建议；`EACCES/EPERM` → 403；`EADDRNOTAVAIL` → 403 + 监听地址说明；远端 `AllowTcpForwarding no` 给针对性提示 |
> | 管理面板 | 全局列表 + 内联启动/停止/删除 + 状态徽标 + 当前/累计连接数 + 上下行字节；面板打开期间 2 s 轮询，关掉即停 |
> | 会话集成 | 会话编辑弹窗内嵌隧道行（最多 32 条/会话）；连接建立时自动启动，失败写进终端提示而不阻断连接；Telnet 记录携带 `tunnels` 直接 400 |

**验收清单（全部通过）**
- [x] `-L 13306:内网MySQL:3306`，本地用客户端成功连上内网库（以本地回显服务替代 MySQL，链路等价）
- [x] `-D 1080`，浏览器配置 SOCKS5 代理后可访问远程内网 HTTP 服务（以手写 SOCKS5 客户端穿透验证，含域名 ATYP）
- [x] `-R` 反向隧道，从远程主机访问到本地服务（mock sshd 真实监听并回送 `forwarded-tcpip`，与真实 sshd 行为一致）
- [x] 关闭会话后端口立即释放（`netstat` 验证 + 重新绑定验证）

## 五、开发环境与运行方式

```bash
# 安装依赖（根目录，workspaces 会一并安装子包）
npm install

# 开发模式：并行启动后端(8080) + 前端(5173，代理到后端)
npm run dev

# 类型检查
npm run typecheck

# 构建生产产物
npm run build

# 启动生产服务（默认 http://127.0.0.1:8080）
npm start

# 指定局域网访问（需显式开启并设置访问密码）
npm start -- --host 0.0.0.0 --port 8080
```
