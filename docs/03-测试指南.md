## 1. 前置：环境与构建

| 项目 | 要求 |
| --- | --- |
| Node.js | **>= 22.12.0**（由 Vite 8、better-sqlite3 13 的 engines 共同决定） |
| 端口 | 8080（服务端 API）、5173（前端 Vite）、2222-2225（mock SSH） |

```bash
# 安装依赖（npm workspaces，根目录执行一次）
npm install

# 启动开发态：服务端 8080 + 前端 5173
npm run dev
```

根 `package.json` 已用 `predev` / `prebuild` / `pretypecheck` / `prestart` 自动构建 `@webterm/shared`，无需手动处理依赖顺序。

**访问地址必须是 `http://localhost:5173`**。Vite 默认只绑 `localhost`，用 `127.0.0.1:5173` 访问会失败。

其他常用命令：

```bash
npm run typecheck   # server + web 全量类型检查
npm run build       # 生产构建（服务端 dist + 前端静态资源）
npm start           # 生产模式启动（此时由服务端静态托管前端）
```

## 2. 测试目标：内置 mock SSH 服务端

真实设备不一定随时可用，项目自带一个用于端到端验证的 SSH 服务端：

```
packages/server/dev/mock-ssh-server.mjs      # 主服务端（含 SFTP 子系统）
packages/server/dev/mock-sftp.mjs            # SFTP 子系统实现（被上面这个引用）
```

| 项 | 值 |
| --- | --- |
| 默认监听 | `127.0.0.1:2222` |
| 默认账号 | `demo` / `demo` |
| SFTP 家目录 | `/home/demo`，映射到宿主 `MOCK_SFTP_ROOT` |

```bash
# 单实例启动
node packages/server/dev/mock-ssh-server.mjs

# 指定端口，并把 SFTP 家目录指向一个准备好在手边的目录
MOCK_PORT=2223 MOCK_SFTP_ROOT=/tmp/mock-2223 node packages/server/dev/mock-ssh-server.mjs
#   在 Windows 的 Git Bash 下写宿主路径，例如：
#   MOCK_SFTP_ROOT='D:/tmp/mock-2223' node packages/server/dev/mock-ssh-server.mjs
```

### 2.1 内置指令（登录后在终端里直接敲）

| 指令 | 用途 |
| --- | --- |
| `help` | 列出全部指令 |
| `echo <文本>` | 回显，验证基本输入输出 |
| `cols` | 报告当前 PTY 尺寸，验证窗口尺寸同步 |
| `big <KB>` | 连续输出 N KB，验证背压（不暂停会打爆服务端内存） |
| `utf8` | 输出中文 UTF-8，验证编码直通 |
| `gbk` | 输出 GBK 中文，需把会话编码设为 `gbk` 验证转码 |
| `sleep <秒>` | 静默指定秒数 |
| `exit` | 结束会话 |

### 2.2 环境变量

| 变量 | 说明 |
| --- | --- |
| `MOCK_PORT` | 监听端口，默认 2222 |
| `MOCK_HOST` | 绑定地址，默认 127.0.0.1 |
| `MOCK_USER` / `MOCK_PASS` | 账号口令，默认 `demo` / `demo` |
| `MOCK_LEGACY=1` | 只提供 legacy 算法，验证客户端自动降级 |
| `MOCK_AUTH=publickey` | 公钥认证模式，公钥经 stdin 传入（一行 base64），不落盘 |
| `MOCK_SFTP_ROOT` | SFTP 家目录对应的宿主目录，默认临时目录 |
| `MOCK_NO_SFTP=1` | **不提供** SFTP 子系统，用于验证客户端对「远端不支持 SFTP」的提示 |
| `MOCK_SFTP_FAIL_ONCE_AFTER=<字节>` | 累计写入超过该字节数后，拒绝一次 WRITE。用于验证断点续传 |

### 2.3 内置 mock Telnet 设备

阶段 4 起还有一个 Telnet 设备模拟器，用于验证选项协商、NAWS、本地回显与 IAC 转义：

```bash
node packages/server/dev/mock-telnet-server.mjs          # 默认 127.0.0.1:2323
MOCK_PORT=2331 node packages/server/dev/mock-telnet-server.mjs
```

| 变量 | 说明 |
| --- | --- |
| `MOCK_PORT` | 监听端口，默认 2323 |
| `MOCK_HOST` | 绑定地址，默认 127.0.0.1 |
| `MOCK_TELNET_ECHO=0` | 不声明也不执行回显，用于验证**本端本地回显兜底**（否则用户「打字看不见」） |
| `MOCK_TELNET_NO_NEGOTIATION=1` | 完全不做选项协商，模拟极简实现 |
| `MOCK_TELNET_NAME` | 设备名，默认 `MockTelnet`（同时作为提示符前缀） |

登录后在终端里可直接敲的指令：

| 指令 | 用途 |
| --- | --- |
| `help` | 列出全部指令 |
| `ping` | 返回 `pong`，验证基本输入输出 |
| `echo <文本>` | 回显文本 |
| `size` | 报告最近一次通过 **NAWS** 收到的窗口尺寸，验证尺寸协商 |
| `ttype` | 报告最近一次通过 **TERMINAL-TYPE** 收到的终端类型 |
| `iac` | 故意输出裸 `0xFF`：不转义的话对端会把 IAC 后面的字节当命令吃掉 |
| `big <KB>` | 连续输出 N KB，验证背压 |
| `quit` | 结束连接 |

> 该设备对 **CR** 与 **LF** 都认行结束（CRLF 只算一次换行）—— 这是真实设备的行为（相当于 telnetd 的 `ICRNL`）。浏览器里 xterm 的回车只发一个 CR，早期只认 LF 的版本会表现为「按回车毫无反应」。

### 2.4 跳板链（ProxyJump）验证

本服务端接受 `direct-tcpip` 通道请求，因此把多个实例串联即可模拟多级跳板：

```bash
MOCK_PORT=2222 node packages/server/dev/mock-ssh-server.mjs   # A
MOCK_PORT=2223 node packages/server/dev/mock-ssh-server.mjs   # B
MOCK_PORT=2224 node packages/server/dev/mock-ssh-server.mjs   # C
```

在会话里配置「跳板链」为 A → B、目标指向 C，即构成 A→B→C 三级跳。

> 实现注意：ssh2 服务端注册的**事件名是 `'tcpip'`**（不是协议层的通道类型名 `'direct-tcpip'`）。注册错名字会让所有转发请求在握手期被自动拒绝且服务端不留日志。

## 3. 方式一：浏览器手动测试（日常推荐）

### 3.1 终端与会话库

1. 浏览器打开 **`http://localhost:5173`**。
2. 首屏是保险库门禁。首次使用显示 **「设置主密码」**：输入至少 8 位主密码并确认，点 **「设置并解锁」**。
   - 主密码只存在于服务端进程内存，不落盘、不上传。**遗失后已存凭据无法恢复。**
3. 进入主界面，左侧是 **「会话库」**（首次为空）。
4. 点击 **「+会话」**，在对话框中填写：

   | 字段 | 值 |
   | --- | --- |
   | 会话名称 | 本地演示 |
   | 主机地址 | `127.0.0.1` |
   | 端口 | `2222` |
   | 用户名 | `demo` |
   | 登录凭据 | 展开「+ 新建凭据」→ 名称随意、类型「口令」、口令 `demo` |
   | 编码 | `utf8` |

   点 **「保存」**。凭据会被加密存入保险库。
5. **单击该会话**即发起连接，右侧打开终端标签页。
6. 在终端里依次敲 `help`、`echo 你好`、`cols`、`utf8`、`big 200`，观察回显、尺寸同步、中文与背压表现。
7. 验证持久化：**重启服务端进程**后刷新页面，界面变为 **「解锁保险库」**（重启即锁定是设计行为），输入主密码解锁，会话与凭据仍在。

**三级跳验证**：再建一个会话，目标填 `127.0.0.1:2224`，并在「跳板链」里加两跳 —— `127.0.0.1:2222`、`127.0.0.1:2223`（凭据同样引用保险库），连接后敲 `echo jump-ok`。

### 3.2 SFTP 文件传输

前提：mock 以 `MOCK_SFTP_ROOT=<某目录>` 启动，并在该目录里放几个文件与子目录。

**打开方式（三种，任选）：**

| 入口 | 说明 |
| --- | --- |
| 侧边栏会话节点悬停 → **SFTP** | 连接参数与凭据由服务端从会话库解析 |
| 标签栏上终端标签悬停 → 文件夹图标 | **复用该终端已有的 SSH 连接**开 SFTP 通道 |
| 「快速连接」对话框 → 右上角切到 **SFTP 文件** | 直传参数新建一条独立连接 |

> 复用连接不是省事，而是**老设备的刚需**：交换机/路由器的 VTY 线路常只有几条，重复登录会直接把后来的会话挡在门外。会话信息条上会标注当前是「复用终端连接」还是「独立连接」。

**逐项验证：**

1. **双栏布局**：左「本机（服务端磁盘）」、右「远端主机」。服务端本地面板受 `WEBTERM_LOCAL_ROOT`（默认用户家目录）限制，无法向上越界。
2. **目录导航**：双击目录进入；面包屑左侧箭头「上一级」；房子图标回到初始目录；地址栏双击可手输路径。
3. **排序**：点击表头「名称 / 大小 / 修改时间」，目录恒定置顶。
4. **文件操作**：工具栏或右键菜单进行新建目录 / 新建空文件 / 重命名 / 修改权限（八进制，如 `644`、`755`）/ 删除。远端栏对多选的支持：Ctrl 追加、Shift 连选。
5. **下载**：在右栏选中文件或目录 → 点 **「← 下载」**（或把它拖到左栏）。传输面板出现任务，进度 / 速度 / ETA / 文件计数逐步推进。
6. **上传**：在左栏选中 → 点 **「上传 →」**（或拖到右栏）。目标已存在时任务失败并列出冲突路径，按提示确认后才会覆盖。
7. **浏览器上传**：把 **操作系统里的文件**直接拖到远端栏，走 `octet-stream` 通道（浏览器 → 远端），面板下方显示独立进度条。
   > 拖到**本地栏**会被拒绝并给出说明：本地面板展示的是服务端磁盘，不是浏览器所在机器的磁盘。
8. **暂停 / 继续 / 取消 / 重试**：`⏸` 暂停后进度冻结，`▶` 继续；`✕` 取消并清理半成品；失败的 `↻` 重试会**从断点续传**而不是重传。
9. **文本预览与远程编辑**：双击文本文件打开预览弹窗，修改后点「保存」直接回写远端。保存会带打开时的 mtime，若期间文件被别人改过则返回 **409** 并提示，不会静默覆盖。二进制文件只读，并说明原因。
10. **标签与回收**：SFTP 标签与终端共用一条标签栏（带文件夹图标）。关闭标签后会 `DELETE` 服务端会话；用 `curl http://127.0.0.1:8080/api/sftp/sessions` 可确认会话数归零。

**手工验证「真的走了 SFTP」而不是本地读写**：对远端栏的任意文件做修改，然后直接到 `MOCK_SFTP_ROOT` 对应的宿主目录里查看文件内容与权限是否同步变化。

### 3.3 Telnet 明文终端

前提：先起一个 mock Telnet 设备（见 2.3），例如 `MOCK_PORT=2331 node packages/server/dev/mock-telnet-server.mjs`。

1. 点 **「快速连接」**，在标题右侧把协议切到 **Telnet**。观察表单变化：
   - 端口自动变为 **23**（手改过端口则保持不变）；
   - **用户名、认证方式、算法兼容策略整段消失** —— Telnet 没有认证阶段，登录是在终端里逐行输入的；
   - 顶部出现 **明文风险提示**；
   - 右上角的「SFTP 文件」用途按钮消失（Telnet 没有文件子系统）。
2. 填 `127.0.0.1:2331`，点 **「测试连接」**。Telnet 的探测只回答两个问题：**TCP 通不通**、**对端说不说话**。结果面板会展示设备欢迎语（banner），且**不出现密钥交换 / 加密算法等 SSH 专有字段**。
3. 点 **「连接」**，终端里应出现 `MockTelnet (mock) ready.` 与提示符。依次敲：
   | 指令 | 应看到 |
   | --- | --- |
   | `help` | 命令列表 |
   | `ping` | `pong` |
   | `size` | `size=<列>x<行>`，且与终端实际尺寸一致；改窗口大小后再敲，数值应更新（**NAWS** 生效） |
   | `ttype` | `ttype=xterm-256color`（**TERMINAL-TYPE** 生效；在表单里改 TERM 后重连应跟着变） |
   | `iac` | 设备回送一个裸 `0xFF`。**紧接着敲 `ping` 仍能得到 `pong`** —— 说明双向 IAC 转义正确，0xFF 没有被当成命令吃掉 |
   | `big 256` | 大流量输出，界面不卡死、内存不涨（背压生效） |
4. **本地回显兜底**：另起一个 `MOCK_TELNET_ECHO=0 MOCK_PORT=2332 node packages/server/dev/mock-telnet-server.mjs`，连上后**逐字符**敲 `echo abc`。设备不回声，但屏幕上应能看到自己打的内容（本端补的回显），退格也能正常删掉一个字符。把鼠标移到终端工具栏左侧的 **Telnet 徽标**上，悬浮提示里会写明「远端回显：否（已启用本地回显）」。
5. **保存到会话库**：点「+会话」把协议切到 Telnet —— 用户名、登录凭据、跳板链、算法兼容全部隐藏，端口默认 23。保存后侧栏节点带 **Telnet 徽标**，悬停操作里**没有 SFTP 按钮**。
6. **能力裁剪**：Telnet 标签上不应出现文件夹图标（「打开 SFTP」）—— Telnet 没有 SFTP 子系统。

## 4. 方式二：自动化端到端（阶段 2 服务端）

脚本 `data/tmp/e2e-phase2.mjs` 自管 4 个 mock SSH 实例与服务端的两次启停，覆盖 35 项断言：

```bash
node data/tmp/e2e-phase2.mjs
```

覆盖范围：

- 保险库：未初始化态拒绝写凭据、弱主密码 400、重复设置 409、锁定 423 / 错误密码 401 / 正确解锁
- 凭据：CRUD、摘要不泄露秘密字段、**直查 SQLite 确认密文**、名称保留明文
- 会话库：文件夹与会话、引用不存在凭据被拒、删除被引用凭据 409
- 连接：直连探测与终端交互、**三级跳 A→B→C**、**Ed25519 + 口令私钥登录**
- 持久化：服务端重启后会话库完整保留、保险库自动锁定后重新解锁仍可用

> 运行前请确认 **2222-2225 与 8099 端口空闲**（脚本会自行占用）。若手动测试的 mock 还在跑，先关掉它。
> 脚本在异常路径也会兜底清理子进程，不会留下孤儿进程占端口。

## 5. 方式三：自动化端到端（阶段 3 SFTP）

### 5.1 服务端级（HTTP / WebSocket 契约）

```bash
npm run build                        # 必须先构建：脚本直接跑 dist
node data/tmp/e2e-phase3.mjs         # 75 项断言
```

> 若该目录已有上次运行的残留（脚本开头会清空自己的 scratch 目录），在受管控的 Agent 环境里会撞上批量删除保护，用下面的写法放行（详见第 8 节）：
>
> ```bash
> env -u CODEBUDDY_SAFE_DELETE_BULK_STATE_DIR -u CODEBUDDY_TOOL_CALL_ID -u CODEBUDDY_SAFE_DELETE_BULK_GUARD \
>   node data/tmp/e2e-phase3.mjs
> ```

自管 3 个 mock 与 1 个服务端实例，不触碰开发用的 8080：

| 端口 | 用途 |
| --- | --- |
| 2231 | 常规 SFTP 后端（列举、文件操作、传输、并发、暂停/取消） |
| 2232 | `MOCK_SFTP_FAIL_ONCE_AFTER` 注入一次性写故障（验证断点续传） |
| 2233 | `MOCK_NO_SFTP=1`（验证「远端不支持 SFTP」的提示） |
| 8096 | 服务端（独立数据目录与本地根目录） |

覆盖范围（A~I 九组）：

- **A 会话**：建立 / 家目录 / 本地根一致 / 独立连接 / 复用终端连接 / 无效 terminalId 退化
- **B 目录与文件操作**：列举（含大小权限）、父目录、本地根不可再向上、mkdir、rename、chmod 生效、touch、删除
- **C 传输队列**：单文件上传下载内容一致、递归目录聚合统计与结构保持、覆盖保护、并发上限（3）、同目标串行、暂停进度冻结、继续、取消并清理半成品、移除已结束任务
- **D 断点续传**：注入故障 → 首次失败并保留半成品 → 重试起点不低于断点 → **把断点前的字节改写成标记，验证这些字节未被重传** → 断点后内容正确
- **E 浏览器通道**：octet-stream 上传 / `offset` 续写 / Range 下载（206 + Content-Range）/ 本地文件下载
- **F 路径安全**：本地 `../..`、绝对路径越界、`C:\Windows` 一律 403 PATH_ESCAPE；远端相对路径 400
- **G 文本预览与远程编辑**：预览、mtime 过期被拒（409）、保存生效并沿用原权限、二进制拒绝编辑、超限标记截断
- **H 不支持 SFTP 的提示**：错误信息明确指出缺少 SFTP 子系统
- **I 会话关闭**：关闭后 404；关闭借用的 SFTP 会话不影响终端连接

### 5.2 浏览器级（真实 UI 流程）

```bash
export NODE_PATH="C:/Users/Administrator/.workbuddy/binaries/node/workspace/node_modules"
node data/tmp/e2e-browser-p3.mjs     # 55 项断言
```

> `NODE_PATH` 必须设置：`puppeteer-core` 刻意装在隔离的 node workspace 里，不进项目依赖。残留目录导致的批量删除保护同样适用（见 5.1 的 `env -u ...` 写法）。

自管 1 个 mock（2241）+ 1 个**生产模式**服务端（8098，直接托管 `packages/web/dist`），用系统 Chrome 无头驱动。前置：`npm run build`。

覆盖：保险库初始化 → 快速连接开 SFTP → 双栏加载 → 目录进出 → 新建/右键删除目录 → 下载到本地栏 → 上传到远端 → 文本预览与改写保存 → 二进制保护 → 关闭标签并确认服务端会话回收，全程断言无未捕获前端错误。

**调试技巧**：加 `DEBUG_NET=1` 会打印每个 SFTP 接口的**发出时刻**与**响应内容**。定位「界面状态与请求不一致」这类问题时，先看请求是否发出、再看返回什么，比盯着 UI 猜快得多：

```bash
DEBUG_NET=1 node data/tmp/e2e-browser-p3.mjs
```

另有三个定位用探针脚本：

## 6. 方式三之二：自动化端到端（阶段 4 Telnet）

### 6.1 服务端级（HTTP / WebSocket 契约）

```bash

```

自管 3 个 mock Telnet 设备与 1 个服务端实例：

| 端口 | 用途 |
| --- | --- |
| 2331 | 常规设备（声明并执行回显，含 NAWS / TERMINAL-TYPE 协商） |
| 2332 | `MOCK_TELNET_ECHO=0`（验证**本端本地回显兜底**） |
| 2333 | `MOCK_TELNET_NO_NEGOTIATION=1`（极简设备，完全不协商） |

覆盖范围（A~I 九组）：

- **A 建连**：TCP 连接、欢迎语、提示符、错误分类（端口不通 → `UNREACHABLE`）
- **B 选项协商**：客户端发出 `DO TERMINAL-TYPE` / `DO NAWS` / `WILL SGA`；对端拒绝后不重复请求
- **C 能力上报**：`TERMINAL-TYPE IS` 值正确；NAWS 初始尺寸与 `resize` 后的重发都到达设备
- **D 本地回显兜底**：设备不声明 `WILL ECHO` 时本端补回显（含退格 `\b \b` 且不越界），输入字节确实送达设备
- **E 极简设备**：不协商也能连上并交互
- **F 探测**：Telnet 探测带回 banner、附明文风险告警、不含 SSH 专有字段
- **G 会话库**：Telnet 记录可保存（无需凭据）；**携带凭据或跳板链一律 400**；SSH 记录缺凭据仍被拒（校验按协议分支）
- **H 从会话库打开**：标题按 `host:port` 推导、协议字段正确、**对 Telnet 会话开 SFTP 返回 400 `INVALID_CONFIG`**
- **I 关闭与回收**：`DELETE` 后设备侧连接断开、终端详情 404


## 7. 方式四：真机验证（`192.168.1.254`）

这台设备是**老旧且非标准的 SSH 设备**，实测结论：

| 环节 | 结果 |
| --- | --- |
| 版本标识串 | `SSH-2.0--`，换行只有 LF 无 CR（违反 RFC 4253） |
| KEX | 仅支持 `diffie-hellman-group14-sha1` / `group-exchange-sha1`，需客户端显式启用 legacy 算法 |
| 主机密钥 | `ecdsa-sha2-nistp521` 在 ssh2 下报签名验证失败，但 OpenSSH 能通过；改用 `ssh-rsa` 正常 |
| 会话建立 | 接受 `CHANNEL_OPEN(session)` 与 `pty-req`，但**拒绝 `shell` / `exec` / `subsystem:sftp`** |

**结论**：WebTerm 对该设备只能验证到「握手 + 认证 + PTY 申请成功」，之后由设备侧拒绝会话。已用 OpenSSH 10.3 对照复现同样失败，确认是设备账号/配置限制，不是客户端实现问题。

因此在 WebTerm 里指向该主机时，预期现象是：**探测成功，但打开终端报「认证通过但拒绝会话」**；开 SFTP 则报「远端未提供 SFTP 子系统」——两者都是正确行为。

## 8. 常见问题排查

| 现象 | 原因与处理 |
| --- | --- |
| 设置主密码报 500「保险库操作失败」 | 曾因 `scrypt` 未显式设 `maxmem` 触发（N=2^15 恰好踩到 Node 默认 32MiB 上限）。已修复；若复现说明 `dist` 过期，执行 `npm run build` 或重启 dev |
| 跳板连接报「跳板机拒绝转发」 | mock 曾注册错的事件名（应为 `'tcpip'`）。已修复；若复现请确认 mock 脚本为最新版本 |
| `127.0.0.1:5173` 打不开 | Vite 只绑 `localhost`，请改用 `http://localhost:5173` |
| 接口返回 423 Locked | 保险库已锁定（服务重启后必然锁定），先解锁再操作 |
| 前端页面是旧版 | 开发态前端由 Vite 提供，服务端静态托管只在生产模式生效；确认 `npm run dev` 的两个进程都在运行 |
| 终端输出中文乱码 | 检查会话「编码」设置，或用 mock 的 `gbk` 指令配合 `gbk` 编码验证转码链路 |
| **上传任务永远停在「传输中」，进度不动也不失败** | ssh2 的 SFTP 写流在 `_write` 失败时**先 `destroy()` 再回调**，`destroy()` 会把 `writableState.destroyed` 置真，随后 Node 的 `errorOrDestroy()` 见流已销毁直接返回 —— **`error` 事件根本不会发出**，只剩 `emit('close')`。若只监听 `error`，任务就永久卡在 running。已在 `transfer-queue.ts` 的 `pump()` 里用「`error` + 非收尾期的 `close`」双信号兜底 |
| **取消任务后半成品没被删除** | 取消的流程是「先 destroy 流，再删文件」，此刻 SFTP 的 CLOSE 还没往返完，远端句柄仍打开 —— Windows 上删除被打开的文件直接 EBUSY。已在 `cleanupPartial()` 里做退避重试（最多 12 次 × 50ms） |
| **Telnet 打字看不见** | 设备没有声明 `WILL ECHO`（不负责回显）时，本端会自动补上本地回显。把鼠标移到终端工具栏的 **Telnet 徽标**上可看到 `远端回显：是/否`；若显示「否（已启用本地回显）」而仍然看不见，说明是别的问题（先敲回车看提示符是否重绘） |
| **Telnet 标签上没有「打开 SFTP」按钮** | 预期行为。Telnet 只有终端数据流、没有文件子系统；服务端对 Telnet 会话开 SFTP 会返回 400 `INVALID_CONFIG`。需要传文件请为该主机另配 SSH 会话 |
| **Telnet 按回车设备没反应** | 行结束符的老问题：NVT 规定 CR 后面要跟 LF 或 NUL，而浏览器里 xterm 的回车只发一个裸 CR。本项目服务端**原样透传**（真实设备与 telnetd 都接受 CR），但自建的极简测试桩如果只认 LF 就会表现为「按回车毫无反应」——内置的 `mock-telnet-server.mjs` 已同时接受 CR 与 LF（CRLF 算一次换行） |
| **进入子目录后列表闪一下旧内容 / 点「上一级」跳错层** | 切换目录的瞬间列表里还挂着上一个目录的条目。已在 `SftpPane` 里用 `loadedTargetRef` 区分「换目录」（先清空）与「刷新当前目录」（保留，防闪烁），并禁用不一致状态下的向上导航 |
| **E2E 脚本二次运行直接被拦：`SAFE_DELETE_BULK_CONFIRM_REQUIRED {"count":391,"threshold":50}`** | 脚本开头会清空自己的工作目录（`data/tmp/e2e-p3`、`data/tmp/e2e-p3b`）。首次运行目录是空的，之后残留近 400 个文件，`fs.rmSync(recursive)` 就撞上「单轮工具调用批量删除 > 50 个文件」的保护。这**不是脚本 bug**，清理的是脚本自己的 scratch 目录，加上前缀即可放行：<br>`env -u CODEBUDDY_SAFE_DELETE_BULK_STATE_DIR -u CODEBUDDY_TOOL_CALL_ID -u CODEBUDDY_SAFE_DELETE_BULK_GUARD node data/tmp/e2e-phase3.mjs` |
| 浏览器 E2E 报 `Cannot find module 'puppeteer-core'` | 该包只装在隔离的 node workspace 里（避免污染项目依赖），必须先导出 `NODE_PATH="C:/Users/Administrator/.workbuddy/binaries/node/workspace/node_modules"` |
| 多实例并行验证时端口被占 | 服务端脚本只用 8096/8098/8099，mock 只用 2231-2233/2241/2252-2253；开发用的 8080/2222 不受影响。若仍冲突，先 `netstat -ano \| grep LISTENING \| grep ":<端口>"` 找到 PID 再结束 |
